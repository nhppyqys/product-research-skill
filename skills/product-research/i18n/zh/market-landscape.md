# 赛道扫描

**用户给的那几个产品不是全集，是样本。**⚠️ 实测：用户给了五个社媒工具，交付的报告只比了这五个，用户问"这个赛道有哪些产品"——这个问题根本没被回答。

---

## 一、凑齐 5 到 8 家

**直接玩家**（同买家、同任务、可替代）至少 4 家，**间接玩家**（上游、下游、或用另一种方式解决同一问题）至少 2 家。

发现路径，按优先级：

1. **品类无关的搜索**——用五槽造词，不带任何品牌名。例：「social media scheduling tool for creators」而不是「Buffer 竞品」
2. **从已知玩家的对比页反查**——各家官网常有 `/vs/xxx` 或 `/alternatives` 页，那是它自己认的竞品
3. **开源生态**——GitHub 上同类项目的 stars 排序，能捞到闭源榜单看不见的玩家
4. **App Store / Product Hunt 同类目**
5. 第三方盘点文章——**只用来发现名字，绝不用来填表格**

⚠️ 实测教训：只用「[产品] competitors」这一种查询，返回的全是 SEO 目录站和盘点文，捞不到真正的同类产品官网。

## 一·五、先分层，再比较 ← 这一步做过一次但没写进流程，于是再也没发生

⚠️ **实测**：分层分析做过一次（那是该报告最有价值的一节），但方法里没有这一步，**下一轮换个产品就整块消失了**。见案例库 **C-20**、**C-24**。

**规则：凑齐玩家之后、比较之前，先问一句"这些玩家干的是同一件事吗"。**

**分层的判据不是功能，是它在客户的工作流里站在哪一段。**用第二节品类五槽里的"输入 → 输出"来切：

- 输入是**已有内容**、输出是**已发布** → 分发层
- 输入是**素材或想法**、输出是**成品内容** → 生成层
- 一个产品同时吃下两段 → 一体化层

**每一层要分别回答**：这一层在扩张还是收缩？**证据是什么**？（价格是否被打到零、头部是否在退、有没有开源替代、融资最多的那家过得怎么样）

**然后才是那个真正值钱的问题：价值正在往哪一层迁移？**

### ⚠️ 但分层结论最容易过拟合，必须用同一把尺子量

⚠️ **实测**：一套漂亮的三层结论，换一天复核只剩一句站得住——支撑它的证据全落在长尾噪声带，**而那正是本方法自己禁止的证据**。见 **C-12**。

**三条硬约束：**

- **每层至少要有一个处在可信区间（约 5 万位以内）的玩家做锚**，全靠长尾玩家撑起来的层，只能说"证据不足"
- **不许一层用趋势、另一层用量级**——同一把尺子量所有层，否则一定得出想要的结论
- **同一层内部出现分化时，如实写分化**（例：生成层里有的在退、有的在涨），**不要为了叙事整齐把它压成一句话**

⚠️ **判据：如果某一层的结论删掉长尾玩家后就不成立了，那它就不成立。**

## 二、每一家必须拿到的六项

缺哪项写哪项缺，不许留空不说明：

| 项 | 去哪拿 |
|---|---|
| 名称与官网 | — |
| **成立时间 / 融资阶段** | 媒体报道、Crunchbase、公司 /about、隐私政策里的法律实体 |
| **员工数（带时间点）** | LinkedIn、招聘页、公开的团队页、第三方公司库 |
| **收入量级（ARR）** | 公开披露、媒体报道、第三方估算（标明是估算） |
| 计价模式与入门价 | 官方定价页 |
| 目标客群 + 一句话差异点 | 官网首页原话 |

**"they have funding" 是废话，"2025 年 3 月软银愿景基金二期投了 $20M，投后估值 $2.15 亿" 才是信息。**

## 三、资本效率表 ← 赛道好不好赚钱看这张

把各家的**累计融资**和**当前 ARR** 放同一张表，算「每融一美元产生多少收入」。

⚠️ 实测样本：

| | 累计融资 | ARR | 每融 $1 产生 | 员工 | 状态 |
|---|---:|---:|---:|---:|---|
| Buffer | $4M ⚠️估算 | **$25.58M** ✅第一方 | — | **76** ✅第一方全员名册 | 已盈利 |
| OpusClip | $68M | $10.3M | $0.15 | 147 | VC 输血中 |

**同一张表放一起，这个赛道的钱好不好赚一眼可见。**Buffer 用极少的钱做出两倍多的收入——说明排期分发是能靠自身现金流活的生意；OpusClip 烧 $68M 做到 $10M——说明视频 AI 那块还在抢地阶段。

⚠️ **这张表混了两种证据等级**：Buffer 的收入与人数是它自己公开看板的第一方数据；融资额与 OpusClip 整行都是第三方估算。**同一张表里两套标准正是 C-14 要防的事**——所以每格都标了来源等级。

**这两个不是一个赛道**，资本结构比产品形态更能证明这一点。

## 三·五、市场规模、份额与格局 ← 前几轮完全缺失

⚠️ **实测失败（用户原话）**："所有竞品的整体规模如何，市场容量如何？产品在整个行业内市场占有率如何？……这一块的整个分析面是完全缺失的，这也是不对的"。

**关键认识：拿不到精确数据，不等于这个分析维度可以不出现。**没有市场份额的官方数据，就用**可获得的代理指标做相对位置**，并写清口径与局限。**整段省略是失职，估算并标明口径是专业。**

### 一、流量份额：Tranco 排名（免费、无需 key、可复现）

```
https://tranco-list.eu/api/ranks/domain/<域名>
```

返回**每日域名排名的时间序列**。

### ⚠️ 先搞清它测的是什么，再用它下结论

⚠️ **实测教训：我一度把它当流量指标用，并据此读出"某产品 30 天流量明显后退"，那个结论站不住。**

Tranco 是**五个来源的排名平均**（30 天窗口，Dowdall 计分），而五个来源测的不是同一件事：

| 来源 | 实际测什么 |
|---|---|
| Chrome UX Report | **真实用户页面访问**（自愿上报的 Chrome 用户）——最接近访问量的一条 |
| Cloudflare Radar | **DNS 查询**（1.1.1.1） |
| Farsight | **被动 DNS 流量**（缓存未命中） |
| Cisco Umbrella | **DNS 查询**，**明确包含非浏览器流量** |
| Majestic | **反向链接数**（多少个 /24 网段指向它）——与访问量无关 |

**所以它是"知名度/显著性"的综合排名，不是流量。**五个来源里三个测 DNS、一个测外链，只有一个测真实访问。

**能用它做什么：**

- ✅ **判断量级**——4 千位 / 2 万位 / 20 万位 / 100 万位是数量级差别，不会看错
- ✅ **比较同赛道玩家的相对位置**
- ✅ **读头部的中期变化**（万位以内的量级，变动百分之十几才算信号）

**不能用它做什么：**

- ❌ **换算成访问量**。它给不出"月访问 30 万"这种数字，与 SimilarWeb 的访问量估算不可互换
- ❌ **读长尾的短期变化**。⚠️ Tranco 自己说明长尾稳定性受各来源抽样方式影响。**在 100 万位量级，几十万位的变动很可能是噪声**——实测踩过：把某产品"30 天退 25 万位"当成流量下滑的证据，而它在 121 万位，那个变动没有解释力。**该保留的结论只有量级本身。**
- ❌ **区分人的访问与机器的请求**。三个 DNS 来源会把 API 调用与后台请求一并计入。⚠️ 曾据此写"对纯 API 产品会系统性低估"，**这条也站不住**——按注册域名聚合时，API 子域的请求很可能已经算进去了，方向可能相反

**写进报告时必须带口径句**：说明这是聚合知名度排名而非访问量，并说明本次结论只依赖量级还是也依赖变化趋势。

⚠️ 实测样本（2026-07-29，社媒分发赛道）：

| 域名 | 排名 | 30 天变化 | 判读 |
|---|---:|---:|---|
| zapier.com | 2,896 | +52 | 断层第一，持平 |
| buffer.com | 4,362 | −82 | 第二，微跌 |
| make.com | 6,767 | −648 | 微跌 |
| opus.pro | 24,410 | **−3,207** | **一个月跌 15%** |
| repurpose.io | 184,825 | +750 | 基本持平 |
| activepieces.com | 212,827 | +14,481 | 涨 |
| postiz.com | 226,411 | +22,844 | 涨 |
| zernio.com | 241,038 | +30,677 | 涨 |
| blotato.com | 347,361 | +12,732 | 涨 |
| ayrshare.com | 923,842 | **+138,952** | 涨幅最猛（基数最低） |

**这一张表直接给出格局与趋势**：新兴的 API-first 与开源玩家全在涨，老牌持平或微跌，**而融资最多的 OpusClip 在明显下滑**。

**口径必须写明**：Tranco 是排名不是访问量；排名数字变小表示位置上升；不同赛道的排名不可跨赛道比较；小站排名波动大。

### 二、其他免费的相对规模代理

**按产品形态选，至少凑够两个维度**，单一代理不可下结论：

| 代理 | 反映什么 | 取法 |
|---|---|---|
| Tranco 排名与趋势 | 注意力份额 | 上面的接口 |
| App Store / Google Play **评论数** | 用户基数下限 | Apple 搜索接口免费 |
| GitHub stars / forks | 开发者关注度（仅开源） | GitHub API |
| npm 包月下载量 | 集成侧真实用量 | npm registry API |
| 第三方 ARR 估算 | 收入量级 | ⚠️ 标为估算 |
| 融资总额与轮次 | 投入规模 | 媒体报道 |
| 官网宣称的用户数 | ⚠️ 仅厂商宣称 | — |

### 三、市场容量怎么处理

**不许直接抄咨询公司的 TAM 数字当事实。**它们口径互相矛盾、常年被夸大。

**允许的三种做法**：

1. **自下而上估**：可数的付费玩家数 × 各家的收入量级 = 已被服务的市场下限。写清这是**下限**，不是 TAM
2. **引用二手 TAM 但降级**：注明机构、年份、口径，写成"某机构估算"，不参与主结论
3. **改问一个能答的问题**：不问"这个市场多大"，问"**头部几家加起来的收入量级**"和"**这个数字在长还是在缩**"——后者可用融资节奏、员工变化、Tranco 趋势三个可查信号回答

### 四、市场份额的表达方式

**不写"占 X%"，除非有官方或权威第三方口径。**改写成可辩护的形式：

> "在本赛道 10 家可比玩家中，按域名排名它位列第 5；头部（Zapier）的排名量级比它高约两个数量级。**按注意力口径它属于长尾，不属于头部。**"

⚠️ **同时必须写清代理的失真方向。**⚠️ 但注意：**"对纯 API 产品系统性低估"这个说法已被推翻**（五源里三个是 DNS，含非浏览器流量，按注册域名聚合时 API 子域会算进主域，方向不确定）——见 **C-13**。

**能写的失真方向**：企业销售制产品的客户经销售接触、日常使用在 `app.` 子域内，官网流量低估其真实规模；**但这层偏差对同赛道所有玩家一致，相对位置仍可读。**

**说清偏差方向，比给一个假精确的百分比诚实；而说不清方向时，就写"方向不确定"。**

## 四、收缩与扩张信号

- **员工数的变化方向**比绝对值重要。⚠️ 但方向必须有可比口径：实测某公司第三方估算从 226 降到 74，看着像砍掉三分之二；**后来从它自己公开的全员名册核到实际 76 人**。第三方估算与真实值方向一致但有偏差，**而"226"那个旧值始终没有第一方来源**。→ **变化方向可以用，但两端必须同源；跨来源比出来的"腰斩"不能当硬证据。**
- **招聘岗位的分布**——在招销售 = 在推增长；只招工程 = 在补产品；不招人 = 在收缩或已稳态
- **changelog 的更新节奏**——周级 = 活跃投入；季度级 = 维护模式；停更半年 = 事实放弃
- **新玩家进入速度**——近 12 个月有没有新品发布、有没有新融资进入这个品类

## 五、空位分析 ← 创业者视角的核心产出

找出 **2 到 3 个没有任何现有玩家填上的空白**。每个空白必须写清四件事：

1. **缺什么**——具体到功能或场景，不是"体验不好"这种
2. **为什么对用户重要**——有证据的痛点，不是推测
3. **建造难度**（低 / 中 / 高）——以及难在哪
4. **先填上能领先多久**——现有玩家补齐它需要多长时间

**空位的证据来源**：用户抱怨里反复出现但没人解决的 · 各家文档都缺的同一块 · 定价结构里所有人都回避的那个维度 · 官网 FAQ 里反复出现的"暂不支持"。

⚠️ 找不到空位时，直接说"这个赛道功能已经收敛，差异化不在功能层"——**这本身就是一个有价值的结论**，比硬编三个假空位强。

## 六、威胁排序

前三名按威胁高中低排，依据三项：

- **资源优势**——融资总额与团队规模
- **功能重叠度**——和目标产品的重合面积
- **迭代速度**——看 changelog 和发布历史，不是看它说自己多快

---

## 七、收尾（必须有，不许停在事实）

- **这个赛道现在值不值得进**——一句话结论加两条支撑证据
- **如果进，从哪个细分切**
- **第一个要做的功能是什么**
- **最该盯着谁**
