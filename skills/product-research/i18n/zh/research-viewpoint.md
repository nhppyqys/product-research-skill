# 视角判定：这一步在所有取证之前

**同一个 URL，四种人问的不是同一件事。用错视角，报告再准确也没有价值。**

⚠️ 实测教训：一次对五个社媒分发工具的调研，交出的是完整的定价对比和站点结构，用户的评价是"完全没有任何价值"——因为他要的是"这个赛道值不值得做"，而交付的是"该买哪一个"。**事实全对，作业类型判错，价值归零。**

---

## 怎么判

**不要问用户"你是哪种视角"作为唯一手段**，先从他的措辞判，判不出再问。

| 用户的话 | 视角 |
|---|---|
| 该买哪个 / 我们要不要上这个 / 迁移成本 / 够不够用 | **采购者** |
| 这个赛道能不能做 / 从哪切 / 有哪些产品 / 我想做一个类似的 | **创业者** |
| 值不值得投 / 护城河 / 增长怎么样 / 这家公司能撑多久 | **投资人** |
| 它怎么做的 / 功能怎么设计的 / 界面长什么样 / 用户在哪卡住 | **产品经理** |

不明确时的默认：给出**一个 URL 加"分析这个产品"**，默认按**创业者**做，因为它的覆盖面最广，另外两种视角要的东西它基本都含。**但要在报告开头写明按哪个视角做的**，让用户能一句话纠正。

多视角可以叠加，但**主视角只能有一个**——它决定哪一节写满、哪一节从简。

---

## 四个视角的交付形状

### 共同底座（三个视角都必须有，不许省）

- **品类判定**（五槽）
- **公司底盘**：成立时间、总部、员工数与变化趋势、累计融资与最近一轮、估值、收入量级、客户数量级、盈利状态
- **举证责任**：每条外部事实带 URL + 逐字引文 + 获取时间
- **不用术语的开篇摘要**（见主方法零之一节）——200 字内说清是什么、卖给谁、赚多少、什么位置、机会与风险
- **功能模块表**（见主方法一·五节）——任何视角都需要先知道这产品有什么
- **相对市场位置**（见 market_landscape 三·五节）——用代理指标，写清口径与偏差方向

⚠️ 实测：一次调研交付时公司底盘全空。后来两次搜索就拿到了 Buffer 员工 74 人（两年前 226）、ARR $22.5M、累计融资仅 $4M、已盈利；OpusClip 融资 $6800 万、估值 $2.15 亿、员工 147、ARR $1030 万。**这两条数据比整份报告里所有价格加起来都重要，而它们只花了两次搜索。**公司底盘从来不是"拿不到"，是"没去拿"。

---

### 产品经理视角

**他要回答的是：这个产品怎么做的、哪里做得好、哪里可以做得更好。**

写满：

- **功能模块表**——业务语言，每个模块解决什么问题、给谁用、在哪个档位（见主方法一·五节）
- **核心用户旅程**——从注册到第一次产生价值，逐步写，标出每一步的摩擦点。**摩擦点从口碑引文取，不凭空写**
- **界面与截图**——至少 3 张真实 UI，每张说明支持了哪条判断
- **差异化 vs 标配**——判据是"竞品官网上找不到对应"，凭感觉标的不算
- **信息架构**——导航怎么分、设置菜单怎么组织，**这反映它认为用户的心智模型是什么**
- **交互摩擦清单**——从负面评论里提取的具体卡点，按出现频次排
- **路线图推断**——从招聘岗位、文档更新时间、模板库内容、最近提交反推它下一步做什么

从简：融资与估值 · 市场容量 · 资本效率

必须收尾于：**它的产品决策里哪三个值得学、哪三个是明显的可改进点。**

⚠️ 实测失败：早期报告交的是 **API 端点分组**——那是工程视角。产品经理看不出"这产品长什么样、怎么用"。**端点清单是证据，功能模块才是产品。**

---

### 采购者视角

**他要回答的是：该不该买、买哪个、花多少、以后好不好走。**

写满：定价九项与归一化对比 · 宣称与事实的差距 · 功能横向对比 · 用户抱怨（不是好评）· 迁移与锁定成本 · 支持与 SLA · 安全合规资质

从简：市场规模 · 融资历史（只需判断"这家会不会倒"，看盈利状态与跑道即可）· 增长率

必须收尾于：**谁该选、谁不该选、签字前必须自己核实的三件事。**

---

### 创业者视角

**他要回答的是：这个赛道能不能进、从哪切、先做什么。**

写满：

- **赛道地图**：5 到 8 家直接与间接玩家，不是用户给的那几个（见 market_landscape）
- **空位分析**：2 到 3 个没有任何玩家填上的空白，每个带建造难度和先发优势时长
- **资本效率对比**：谁用多少钱做到了多少收入。⚠️ 实测这一格最能说明问题——Buffer 用 $4M 融资做到 $22.5M ARR 且盈利，OpusClip 用 $68M 做到 $10.3M ARR，**同一张表放一起，赛道的钱好不好赚一眼可见**
- **单位经济**：从各家定价结构反推毛利与获客承受力
- **竞争密度与收缩信号**：⚠️ 实测 Buffer 两年内从 226 人减到 74 人——**赛道老大在裁员保利润，这是"成熟、增长见顶、利润被压缩"的硬证据**，比任何 TAM 数字都有说服力
- **切入点建议**：先占哪个细分、先做哪个功能

从简：逐项功能对比表 · 迁移成本

必须收尾于：**这个赛道现在值不值得进、如果进从哪个细分切、第一个要做的功能是什么。**

### ⚠️ 关于市场规模

**TAM/SAM/SOM 这类数字，公开网上只有咨询公司的二手估算，质量很差，口径互相矛盾。**

规则：可以引用，但**必须标明是二手估算并给出机构名与年份**，不许当成事实陈述。

**优先用可验证的替代信号**——它们是硬证据，而 TAM 不是：各家的 ARR 与客户数（可查）· 员工数变化（可查）· 融资总额与轮次节奏（可查）· 招聘岗位分布（可查）· changelog 迭代速度（可查）。

---

### 投资人视角

**他要回答的是：这家公司值不值得投、能不能守住。**

写满：

- **公司底盘的完整版**：ARR 及其增长、员工数变化曲线、融资历史逐轮（金额、时间、领投方、估值）、烧钱率与跑道推断、盈利状态
- **资本效率**：每融一美元产生多少收入
- **护城河的证据**，不是形容词：转换成本、网络效应、数据壁垒、分发优势、许可证结构。⚠️ 实测 Postiz 用 AGPL-3.0 开源，33,900 stars——**这既是分发优势也是护城河漏洞：任何有工程团队的客户都可以永久自托管、永不付费**
- **市场结构**：赢家通吃还是长尾并存，看头部集中度与价格离散度
- **留存与扩张信号**：定价里有没有随用量自然增长的维度、有没有企业档、有没有 API 与生态
- **风险**：见主方法第八节

从简：功能逐项对比 · 采购决策建议

必须收尾于：**这笔投资的核心赌注是什么、什么情况下这个赌注不成立。**

---

## 一条通用规则：每一节必须以判断收尾

⚠️ 实测失败：交付了一份完整的价格表和站点状态清单，每一格都准确，但没有一节给出"所以你该怎么做"。用户的原话是"完全没有任何价值"。

**事实清单不是分析。**每一节写完，加一句"所以"。写不出那句"所以"，说明这一节不该在报告里。
